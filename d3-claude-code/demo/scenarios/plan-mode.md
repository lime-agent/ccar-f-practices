# 3.4 — Plan Mode vs Direct Execution 판단 워크북

실행형 시드가 아니라 **"언제 쓰나" 판단** 실습이다. 각 상황에 어느 쪽이 맞는지 골라보고, 근거를 적어본다.

## 기준 요약
- **Plan Mode** = 대규모 변경 · 여러 유효한 접근 · **아키텍처 결정** · 다중 파일 수정.
  변경 확정 전 **안전한 탐색·설계** → 값비싼 재작업 방지.
- **Direct Execution** = 단순·명확 범위(예: 한 함수에 validation 하나 추가, 명확한 스택트레이스 단일 파일 버그).
- **Explore 서브에이전트** = 장황한 발견 출력을 격리하고 요약만 반환 → 메인 컨텍스트 보존(컨텍스트 고갈 방지).

> 함정: "항상 Plan Mode" / "절대 Plan Mode" 는 **둘 다 오답**. 규모·아키텍처 함의로 판단.

2. 날짜 validation 조건 하나 추가 → ?
3. 마이크로서비스 재구성(여러 접근 가능) → ?
4. 명확한 스택트레이스가 있는 단일 파일 버그 수정 → ?
5. 대규모 코드베이스 구조를 먼저 파악(장황한 탐색) → ?
6. "조사는 plan, 구현은 direct" 를 결합하는 예를 하나 써보기 → ?
