# 3.5 — 반복 정제(Iterative Refinement) 기법 워크북

산문 설명이 일관되지 않게 해석될 때, 결과를 점진적으로 개선하는 4가지 기법. 각 기법을 짧게 시연해본다.

## 기법
1. **구체적 입출력 예시** — 산문이 흔들릴 때 가장 효과적. 기대 변환을 2–3개 입력→출력 쌍으로 고정.
2. **Test-driven 반복** — 기대 동작·엣지케이스·성능 요건을 담은 테스트를 **먼저** 작성 → 실패를 공유해 개선 유도.
3. **Interview 패턴** — 구현 전에 Claude가 질문하게 해서, 놓친 설계 고려사항(캐시 무효화, 실패 모드)을 드러냄.
4. **이슈 묶기 vs 순차** — 서로 **상호작용**하는 수정은 한 메시지에 모두 / **독립** 이슈는 순차로.

## 미니 실습 (Claude Code에서)
- (1) "날짜 문자열을 정규화하라"를 **예시 3쌍**과 함께 다시 요청 → 결과 차이 관찰.
- (2) 빈 배열·null 입력 케이스를 담은 테스트를 먼저 주고 "통과시켜라" → 반복.
- (3) "결제 재시도 로직을 설계하기 전에 나에게 5가지를 먼저 물어봐" → interview 패턴 관찰.

> 확인 포인트: 예시/테스트를 준 쪽이 산문만 준 쪽보다 **엣지케이스**를 얼마나 더 잘 처리하는지.
